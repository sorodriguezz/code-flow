Porting the transversal `WF-PR-REVIEWER` runbook (Azure DevOps PR review methodology) into the **code-flow** app as the default PR-review base. Requested 2026-07-27.

Design agreed with the user:
- The methodology lives as a **per-workspace "Review Standard"** (not global, not project-specific logic) — seeded by default, editable in a Settings window, acting as the base review prompt.
- Kept project-agnostic; repo-specific rules stay in the existing "Context" / "MD files" sections.
- Output format MUST stay compatible with `src/lib/parseAnalysis.ts` (the `📈 CALIDAD` line + `### emoji [Severidad · Tipo] Categoría · F-NNN` finding format) or PR-comment posting breaks.

Phases (ALL DONE — both `cargo check` and `pnpm build` green):
1. **DONE** — per-workspace review standard: `ai::DEFAULT_PR_REVIEW_STANDARD`, table `workspace_review_standards` (seed on create + backfill migration), queries `get/set_review_standard`, commands `get/set/default_workspace_review_standard`, `review_pull_request` uses it as prompt, new `ReviewStandardSettings.tsx` section. Global "review" row removed from `PromptTemplates.tsx`.
2. **DONE** — levels (básico/completo/ultra): `ai::review_level_directive` appended to prompt; `level` threaded through `review_pull_request` cmd → `reviewPullRequest` → `prStore.reviewLevel`/`setReviewLevel`; `ReviewLevelSelector` in AiPanel.
3. **DONE** — review memory in **SQLite** (user chose DB over files): table `review_runs` (id=job_id, project_id, workspace_id, pr_id, iter, level, meta JSON, review_md, diff, findings JSON, created_at) + index. Written in `ado_cmd::persist_review_run` inside the same conn lock as `job_history`. Everything lives in `codeflow.db` — no files on disk, no open-folder button (both removed).
4. **DONE** — incremental re-review: `review_memory::reconcile` compares against the previous run's `review_runs.findings` (identity = file|category), tags findings nuevo/persiste/resuelto, prepends `delta_banner` ("🔁 Re-revisión…") to the returned review. `review_memory.rs` is now pure logic (parse_findings/reconcile/delta_banner); all SQL is in `db::queries` (count_review_runs, latest_review_findings, add_review_run). Finding parse in Rust mirrors `parseAnalysis.ts` HEADER_RE (kept as a shared contract).

5. **DONE — consolidation (user asked to de-fragment the settings).** All per-workspace review config lives in ONE settings section **"Revisión de PR"** (`SettingsSectionId "review"`, component `ReviewSettings.tsx`) with sub-tabs: Estándar · Contexto · Instrucciones .md · Descripción PR · Memorias. Removed the separate `reviewStandard`/`context`/`mdFiles` nav entries (and updated CommandPalette + the AiPanel "configure" deep-link to `openSettings("review")`).
   - Generalized the per-workspace prompt storage: table `workspace_prompts(workspace_id, kind, content, updated_at)` keyed by `kind` ("review_standard" | "pr_description"). Migrated `workspace_review_standards` into it and dropped that table. Queries `get/set_workspace_prompt` + `workspace_prompt_default`; commands `get/set/default_workspace_prompt`. Reusable frontend editor `WorkspacePromptEditor.tsx` (kind-parameterized).
   - **PR description template moved from global to per-workspace** (`generate_pr_description` now reads `get_workspace_prompt(kind="pr_description")`); removed the "review" and "PR description" rows from the global `PromptTemplates.tsx` (commit/analyze/conflict remain global).
   - **Memory manager** (`ReviewMemoriesSettings.tsx` + backend cmds `list_review_runs`, `get_review_run`, `delete_review_run`, `delete_review_runs_for_pr`, `purge_workspace_review_runs`, `export_review_runs`): list runs grouped by PR, view saved review, delete run / delete PR history / purge workspace / export to .md/.json via folder dialog.
   - **Provider-neutral by design** (user requirement "que funcione con todos los modelos"): everything routes through `AiTask::Review`/`AiTask::PrDescription` and provider-independent prompt text — nothing tied to Claude.

6. **Parity gaps vs WF-PR-REVIEWER (user asked to close all four).** Status:
   - **DONE — Gap 2 (state + stable IDs + traceability):** `MemoryFinding` gained `estado` (abierto/posteado/resuelto/falso_positivo/ignorado), `thread_id`, `introducido_en_iter`, `resuelto_en_iter`, `motivo_descarte`. `reconcile` now carries forward resolved/discarded findings (never deleted), keeps stable ids for persisters, and appends `resolved_history_section` (🕘 resueltos + 🗂️ descartados) to the review.
   - **DONE — Gap 1 (efficient re-review):** stores `meta.head_sha`; fast-path returns "sin cambios" when head SHA unchanged; `changed_files_between` (git) feeds `reconcile` so findings on untouched files auto-persist instead of looking resolved. NOTE: the model is still fed the full PR diff (quality over token-savings) — only the reconciliation is changed-file-aware.
   - **DONE — Gap 4 (marking, provider-neutral part):** `mark_review_finding` cmd + `RunFindings` UI in the memory manager (mark ignored/false-positive/clear); carried forward on re-review.
   - **DONE — Gap 3 (re-post without duplicating threads), both providers:** posting is now finding-aware. `post_pr_review_comment` cmd takes `run_id` + selected `items` + `postSummary` + `summary`; matches each item to the stored finding by identity, then: no thread → open one (capture id), active+thread → reply "sigue presente", resolved+thread → reply + mark thread resolved. Thread ids written back to `review_runs.findings`. ADO: `post_pr_comment_anchored`/`post_pr_comment` now return the thread id; added `reply_pr_thread` + `set_pr_thread_status` (2=fixed). GitHub: comment fns return id; added `reply_pr_review_comment` + `resolve_review_thread_for_comment` (GraphQL `resolveReviewThread`, best-effort) + `graphql_root`.
   - **DONE — Gap 4 selection:** per-finding checkboxes + "post summary" toggle in the review panel (`AiPanel`); `publish` sends only chosen findings + `job.id` as run id. `buildReviewComments` no longer used for posting.
   - **DONE — Gap 4 fix-pack:** `buildFixpack(parsed, prId)` (schema `pr-review-fixpack/v1`, action-renamed fields) + a "Fix-pack" copy button in the review panel. Delivered as a copyable/exportable artifact (provider-neutral) rather than an auto-attachment — avoids the fragile ADO attachments API + the fact GitHub has no PR attachments. Auto-attach-to-PR remains a possible follow-up.

**All four parity gaps closed. Everything compiles (cargo check + pnpm build green). NONE of it has been run live against real ADO/GitHub APIs — the posting/reply/resolve/GraphQL paths are written to spec but untested; needs a real re-review + re-post to validate.**

7. **DONE — merged Context + Instructions (user found the 3 sub-tabs confusing).** They were functionally IDENTICAL (both just `(name, content)` blocks folded into the prompt in review/analyze/chat; "Instructions/.md" never wrote a file, and "CLAUDE.md" was a misleading default — content is provider-neutral). Merged into ONE "Contexto" tab backed by `review_contexts` with a chips+per-block editor (`ReviewContextEditor.tsx` rewritten). Migration `migrate_md_files_into_contexts` moves old md rows into `review_contexts` then drops `workspace_md_files`. Removed the whole md-files stack: table, `WorkspaceMdFile` model/type, queries, 3 commands, lib.rs registrations, `MdFilesSettings.tsx`, and the md `.extend()` at all 3 injection sites. Review section tabs now: **Estándar · Contexto · Descripción PR · Memorias** (was 5, now 4). "Descripción PR" kept separate (different AiTask).

8. **DONE — Skills management upgrade (user request).** `enabled` column on `workspace_skills` (+ migration) with a per-skill on/off switch; `sync_skills_into_project` copies only enabled skills and removes disabled managed ones from a project's `.claude/skills` (never touches unmanaged folders). Custom skills: `create_custom_skill` (name + SKILL.md in-app) and `import_skill_from_folder` (local folder with a SKILL.md). Full in-app file editing per skill: `list/read/write/delete_skill_file` (path-safe) via a `SkillFilesEditor` (file chips + per-file editor, save on blur, add/delete). `SkillsSettings.tsx` rewritten; `WorkspaceSkill` gained `enabled`. UI notes that skills only apply to Claude Code.

Guía + Etapas reuse `workspace_prompts` (kinds `sdd_guide`/`sdd_stages`) via existing get/set/default_workspace_prompt — no new prompt commands. `workspace_prompt_default` returns the guide for `sdd_guide` and "" for `sdd_stages`. New module `src-tauri/src/sdd.rs`. PENDING (phase 2, user chose "panel propio"): an operational **feature board** main panel (kanban by stage, read/write repo files) + runnable harness scripts — not built yet; only the Settings config + guide exist so far.
